搜索下拉正在加载时，用户通常还可以调整其他筛选条件；保存一张表单时，需要锁定的是这次提交涉及的字段和按钮。loading 放在操作附近，页面其他区域就能继续使用。

请求层默认不显示全局遮罩，由调用方根据操作范围选择按钮、表格、卡片或整页反馈。并发请求各自管理状态，互相独立的模块也能先后呈现结果。

## 按操作范围选择反馈

| 场景 | 加载反馈 | 仍可进行的操作 |
| --- | --- | --- |
| 搜索建议 | 下拉面板 loading | 输入下一段关键字、调整其他条件 |
| 列表查询 | 表格 loading，保留筛选栏 | 修改筛选、取消查询 |
| 表单保存 | 保存按钮 loading，禁用当前表单 | 查看其他区域 |
| 文件导出 | 导出按钮或任务进度 | 继续浏览页面 |
| 登录态切换 | 登录区域或应用级过渡状态 | 按会话切换规则控制 |

登录和退出是否使用全局遮罩，取决于页面还有哪些有效操作。最终权限仍由会话状态决定，加载动画负责表达进度。

## 请求层只在需要时启用全局反馈

```ts title="请求包装"
interface RequestOptions {
  params?: Record<string, string>
  signal?: AbortSignal
  globalLoading?: boolean
}

async function request<T>(path: string, options: RequestOptions = {}): Promise<T> {
  const url = new URL(path, window.location.origin)
  for (const [key, value] of Object.entries(options.params ?? {})) {
    url.searchParams.set(key, value)
  }
  const handle = options.globalLoading ? startGlobalLoading({ signal: options.signal }) : null
  try {
    const response = await fetch(url, { signal: options.signal })
    if (!response.ok) throw new Error(`请求失败：${response.status}`)
    return await response.json() as T
  } finally {
    handle?.close()
  }
}
```

这里只展示 GET 请求。业务项目的请求层可以继续处理认证、响应校验和错误映射。局部 loading 留给组件，便于与现有内容、重试入口和错误提示放在一起。

## 每次全局加载有自己的句柄

多个请求共用一个布尔值时，先完成的请求可能提前关闭其他请求的遮罩。每次调用持有独立句柄，或使用统一服务中的计数和 token，关闭时只释放自己的那一份。

```ts title="句柄的清理逻辑"
interface StartOptions { timeout?: number; signal?: AbortSignal }
interface GlobalLoadingHandle { close(): void }

function startGlobalLoading({ timeout = 10_000, signal }: StartOptions = {}): GlobalLoadingHandle {
  if (signal?.aborted) return { close() {} }
  // mountOverlay 创建本次遮罩，并返回对应的移除函数。
  const removeOverlay = mountOverlay()
  let closed = false
  let timer: ReturnType<typeof setTimeout> | undefined
  const close = () => {
    if (closed) return
    closed = true
    if (timer !== undefined) clearTimeout(timer)
    signal?.removeEventListener('abort', close)
    removeOverlay()
  }
  timer = setTimeout(close, timeout)
  signal?.addEventListener('abort', close, { once: true })
  return { close }
}
```

完成、取消和超时都调用同一个 close，计时器与事件监听一起释放。`mountOverlay` 可由 React Portal 实现，也可接到应用的 UI 服务中。

超时关闭遮罩只改变反馈方式，请求可能仍在执行。长任务可切成后台任务提示，保留进度或重试入口；会话切换、付款等动作的可操作范围继续由业务状态控制。

## 搜索请求只接收最新结果

```tsx title="局部搜索状态"
function useSearch() {
  const controllerRef = useRef<AbortController | null>(null)
  const [loading, setLoading] = useState(false)
  const [data, setData] = useState<Item[]>([])
  const [error, setError] = useState<string | null>(null)

  useEffect(() => () => controllerRef.current?.abort(), [])

  const search = useCallback(async (keyword: string) => {
    controllerRef.current?.abort()
    const controller = new AbortController()
    controllerRef.current = controller
    setLoading(true)
    setError(null)
    try {
      const result = await request<Item[]>('/api/search', {
        params: { keyword }, signal: controller.signal,
      })
      if (!controller.signal.aborted) setData(result)
    } catch (error) {
      if (!controller.signal.aborted) {
        setError(error instanceof Error ? error.message : '查询失败')
      }
    } finally {
      if (!controller.signal.aborted) setLoading(false)
    }
  }, [])

  return { search, loading, data, error }
}
```

新查询取消旧查询，组件卸载也取消当前请求。旧响应、旧错误和旧 finally 都检查 signal，避免把新查询的状态覆盖掉。保留上次结果时，页面可以显示“正在更新”或“更新失败”，让用户知道当前数据是否对应最新条件。

对于不支持取消的 SDK，同样的状态隔离可以用请求序号或 effect 内的 active 标记完成。请求取消减少无用工作，响应归属检查保证界面采用正确结果。

独立模块各自加载后，再按具体场景加入缓存、请求合并和渐进式渲染。用户看到的反馈范围，应与这次操作影响的数据范围一致。
